# 深廣 在庫管理デモ

**[公開デモを開く](https://ss4gdev.github.io/fukahiro-inventory-demo/)**

PC・スマートフォンのブラウザで試せる在庫管理の操作デモです。商品・場所・数量・担当者・仕入先は架空のサンプルで、実際の業務ルールの採用や本番運用を意味しません。

## 四つの操作場面

| 画面 | 内容 |
| --- | --- |
| 在庫一覧 | 商品・保管場所・数量・単位の確認、商品・ロット検索、拠点・場所の絞り込み |
| 入出庫 | 入荷でロットを作成、使用で対象ロットの残量を減算。kg/gのみ固定換算し、尾・本・パックは整数で管理 |
| ロットと期限 | 入荷情報・残量・消費期限・賞味期限・期限不明の確認と絞り込み |
| 権限と履歴 | スタッフ／マネージャー切替、操作履歴、マネージャーによる理由付き数量訂正 |

すべての役割でスマートフォンから主要操作を行えます。PCでは幅を使って在庫一覧や履歴を表示します。

## 試し方

1. 「在庫一覧」でA店（仮）の「とらふぐ 切身（仮）」の「使用」を押します。
2. ロット「DEMO-001」を選び、数量500・単位gを登録します。初期状態ならA店の在庫は7.5kgから7kg、対象ロットは4.3kgから3.8kgになります。
3. 「ロットを見る」「履歴を見る」で登録内容を確認します。
4. 右上でマネージャーに切り替え、直前の使用履歴から数量を0.3kgへ訂正します。訂正理由を入力すると、対象ロットは4kgとなり、元の数量と訂正理由が履歴に残ります。
5. 「入出庫」で入荷も試せます。期限が分からない場合は期限の種類を「不明」にします。

「初期データに戻す」で、このブラウザ内の入力を消してやり直せます。初期データの日付は初回表示・リセット時の日本時間を基準に作成します。通常の再読み込みでは入力内容を保持します。

## データとデモの制約

- 入力はブラウザのlocalStorageに保存します。**端末間・ブラウザ間でデータは共有されません。** 一つのタブで試してください。
- **公開URLとローカルURLは別の保存領域です。** ローカルで入力したデータは公開サイトに移動しません。同じブラウザでも公開サイトは独立した初期データから始まります。
- 在庫情報を保存するサーバーや共有DB、同期、同時更新対策、バックアップはありません。ブラウザの保存データ削除などで入力内容が失われる場合があります。
- 役割切替は操作の比較用で、本人認証や本番のアクセス制御ではありません。実際の権限ルールは未確定です。
- 期限表示は日付の分類であり、食品の安全性や使用可否を判定しません。
- 実在庫・顧客情報・機密情報の投入を想定していません。実EC連携、発注送信、店舗間移動、予約引当、棚卸等は対象外です。
- スマートフォン幅・PC幅でブラウザ検証しています。実機スマートフォンのSafari、キーボード、日付入力UIは未確認です。

## ローカルで起動

Node.jsが使える環境で、このリポジトリのフォルダーに移動して実行します。外部パッケージのインストールやビルドは不要です。

```sh
node server.mjs
```

[ローカルデモ](http://127.0.0.1:4173/) を開きます。ローカルサーバーはそのPCの127.0.0.1のみで待ち受けます。別端末から試すときは上記の公開デモURLを使ってください。停止は実行中のターミナルでCtrl+Cです。

## 公開構成

- `dist/`：HTML・CSS・JavaScript・在庫計算。外部CDNは使いません。
- `server.mjs`：任意のローカル確認用サーバー。
- `.github/workflows/pages.yml`：mainブランチ更新時、distだけをGitHub Pagesへ配信。

[GitHub公式のPagesワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)を利用しています。リポジトリ配下のURLに対応する相対パスでファイルを読み込みます。
